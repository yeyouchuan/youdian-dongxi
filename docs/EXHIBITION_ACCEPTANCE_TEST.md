## 1. 测试目标

确认展会版本能够稳定完成以下演示主线：

1. App 手动连接 MQTT Broker。
2. 正确识别雷达新帧、缓存保活和数据中断。
3. 观众界面只展示 `heart_med`、`breath_med` 和目标距离。
4. 目标距离不在 60–120 cm 时给出调整提示，但不丢弃生命体征。
5. FSR 姿态数据缺失时，雷达生命体征演示仍可独立完成。
6. 发布包可以打开只读连接详情页，且不包含手工注入或 JSONL 回放入口。

## 2. 测试准备

### 2.1 硬件与网络

- [ ] XIAO ESP32-C6 已烧录展会固件。
- [ ] MR60BHA2 雷达立起并正对受测者胸口，距离保持在 0.6–1.2 m。
- [ ] 雷达正前方和正后方没有其他人员，避免单目标被抢。
- [ ] 使用墙充，或已开启充电宝小电流模式。
- [ ] iPhone、雷达板和 Broker Mac 均连接 `ADVX-Players`。
- [ ] 固件中的 `MQTT_HOST` 与 Mac 当前 IP 一致；换网后已经重新烧录。
- [ ] Mac 防火墙允许 TCP 1883、WebSocket 9001 和需要的本地网络访问。

### 2.2 启动 Broker

```bash
cd ~/zuodian/radar
uvx --from amqtt amqtt -c broker.yaml
```

确认：

- MQTT TCP：`<Mac IP>:1883`
- MQTT WebSocket：`ws://<Mac IP>:9001`
- 雷达主题：`zuodian/radar`

### 2.3 标准雷达消息

```json
{
  "heart": 97.0,
  "heart_med": 110.0,
  "breath": 16.0,
  "breath_med": 17.0,
  "dist": 68.9,
  "seq": 88
}
```

验收口径：

- `seq` 必须是非负安全整数。
- 新 `seq`（包括设备重启后序号变小）表示新帧。
- 相同 `seq` 表示缓存保活，不产生新的健康数据。
- 心率只使用 `heart_med`，有效范围 40–150 BPM。
- 呼吸只使用 `breath_med`，有效范围 6–30 次/分。
- `heart`、`breath` 只用于连接详情诊断，不能回退到观众界面。
- 超过 15 秒没有新 `seq`，雷达状态必须显示“已中断”。

## 6. 快速排障

| 现象 | 优先检查 | 处理 |
|---|---|---|
| MQTT 无法连接 | iPhone/Mac 是否同一 WiFi、Broker 地址、9001 端口、本地网络权限 | 修正设置页地址；确认权限；重启 Broker |
| MQTT 已连接但一直等待数据 | 固件 Broker IP、雷达供电、主题 `zuodian/radar` | 同步 Mac IP 后重烧；检查供电和串口 |
| 一直显示缓存保活或已中断 | `seq` 是否变化、雷达是否产生新帧 | 调整雷达朝向和目标；必要时重启雷达 |
| 距离突然跳到其他人 | 单目标被波束内他人抢占 | 清空雷达正前/正后方人员并重新对准 |
| 充电宝几十秒后断电 | XIAO 电流过小导致自动关断 | 使用墙充或充电宝小电流模式 |
| Broker 连本机都拒绝 | amqtt 进程卡死 | 结束旧进程并按第 2.2 节命令重启 |
| App 从后台回来状态异常 | MQTT 会话是否已恢复、是否出现新 `seq` | 重新连接；等待一帧新数据；必要时冷启动 App |
